Write an observation into the daemon's stream. The observation becomes immediately queryable via `query_observations` and triggers any matching subscriptions.

Use this to:
- Log a debugging note: app="my-session", data={message: "investigating auth bug"}.
- Record a state snapshot before/after a change: kind="state_snapshot", data={before, after}.
- Alert other agents: severity="warn" or "error" pushes a real-time alert to subscribed sessions.
- Send a message to another agent: app="agent-a", data={message: "found the bug in auth.rs:42"}. The other agent reads it via `query_observations` with origins=["app:agent-a"].
- Emit a metric: kind="metric", data={name: "response_time", value: 3.2}.

Parameters:
- kind: string. Required. One of: log, query, http_exchange, exception, js_exception, lifecycle, state_snapshot, metric, custom.
- severity: string. Required. One of: trace, debug, info, warn, error.
- app: optional string. Application/origin tag (e.g. "my-api", "agent-name"). Defaults to the calling MCP session's app id.
- data: optional object. Free-form payload. Conventional field: `data.message` for a clean alert/log line.
- tags: optional list of strings. Free-form retrieval tags.
- correlation_id: optional string. Tie multiple observations to the same logical operation.

Returns: { id: <int>, kind, severity, ... full observation echo }. The id is monotonic and references the new row.

Mutating. Observations are append-only; once written, they remain in the store until cleanup runs against retention.
